## 실제 취득과 범위

- 기존 외부 KIS CSV와 SSE 110일 캐시/manifest를 우선 재사용했다.
- SSE 공식 `https://yunhq.sse.com.cn:32042/v1/sh1/dayk/{symbol}`에
  `begin=-500&end=-1&period=day&select=date,open,high,low,close,volume,amount` 요청.
  첫 호출 1회 성공 후 나머지 11회 순차 호출, 호출 사이 최소 2초, 재시도 없음.
  KIS 호출은 없었다. 500은 요청 창이며 응답은 실제 **499거래일**이다.
- 12종 모두 2024-10-15~2026-11-03 SSE 응답을 확보했다. 당일 응답은 완료일봉 또는
  완료 주봉의 증거가 아니며, KIS와의 대사는 마지막 보유일 2026-10-27까지만 가능하다.
- 원문은 checkout 외부 `CHINA_PRIVATE_SNAPSHOT_DIR/sse_history/<요청 URL SHA256>/`
  아래에만 저장했다. 기존 `sources/`·`market_manifest.json`·KIS CSV는 덮어쓰지 않는다.
  각 응답의 URL·취득 UTC·HTTP 상태·바이트 해시·경로 영수증을 보존한다.
  로컬 해시는 바이트 동일성 근거이며 출처 진위나 조정 검증을 증명하지 않는다.
- 오프라인 재실행에서 12종 모두 캐시 재사용, 네트워크 호출 **0회**를 확인했다.

## 재현 방법

```powershell
$env:CHINA_PRIVATE_SNAPSHOT_DIR = 'C:\private\china-history'
$env:PYTHONUTF8 = '1'
# 기존 감사 입력: china_candidate_prices.csv, market_manifest.json, sources/
# 기본은 오프라인. 기존 캐시 + 장기 요청 캐시를 각각 독립 감사한다.
python china_sse_history_collect.py --as-of-date 2026-11-03
# 네트워크 필요 시 명시적으로 호출 예산 지정. 기본 1회, 최대 12회.
python china_sse_history_collect.py --as-of-date 2026-11-03 --fetch --max-requests 1
python -m pytest -q tests/test_china_sse_history_collect.py tests/test_china_history_audit.py tests/test_china_readiness_validation.py tests/test_china_stage_guard.py
```

리다이렉트 거부, 응답 2MB 제한, TLS 검증, 15초 타임아웃을 적용했다.
첫 네트워크/응답 검증 실패 뒤에는 추가 호출하지 않는다. 실패·중단 흔적과 원문은
보존하며 같은 요청을 자동 덮어쓰기/재시도하지 않는다. 필요 시 다른 `--sessions`
(200~1000) 창을 선택하면 별도 요청 캐시가 된다. 재시도 여부는 실패 원인을 먼저
조사해 결정한다. KIS API 키나 토큰을 요구하지 않으며 예외/원문 가격을 stdout에
출력하지 않는다. Git checkout 내부 또는 그 내부로 연결되는 심볼릭 링크 입력은 거부한다.

기존 `china_history_audit.official_daily`, `audit_symbol`, `audit_snapshot` 및
`china_stage.validated_daily`를 재사용한다. 응답이 짧아도 실제 일수/주봉만 계산한다.
불일치·누락을 건너뛰거나 서로 다른 취득 시점의 가격을 이어 붙이지 않는다.
기존/장기 스냅샷 각각의 결과를 출력하고 연속 일치가 긴 결과를 길이 진단에 사용한다.
출력은 기간·개수·입력 해시·검증 상태뿐이다. 앱/차트 로더에 연결하지 않았다.
